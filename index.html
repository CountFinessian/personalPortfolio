               Interactive Simulation Scenarios — What Each Scenario Does
            

            

              
            

          

          

            
            

              

                Scenario 1: Subnet Broadcasts & Layer-2 Flooding
                Layer 2 (Data Link)
              

              

                What is happening: Host A transmits an ICMP broadcast frame to 10.0.0.255 (MAC FF:FF:FF:FF:FF:FF). Custom switch.py learns the source MAC address and floods the raw Ethernet frame out to all connected ports (Host B and Router R1) without dropped packets.
              

              
Component Tested: switch.py (Layer 2 Learning Switch)

            


            

              

                Scenario 2: Static Multi-Hop Forwarding
                Layer 3 (Network Routing)
              

              

                What is happening: Host A pings Server D across 4 router hops (R1 → R2 → R3 → R4). Each router uses forwarding_table.py with bitwise CIDR Longest Prefix Matching (LPM) to look up next-hop interfaces and decrement TTL.
              

              
Component Tested: forwarding_table.py & prefix.py (CIDR LPM Table)

            


            

              

                Scenario 3: Distance-Vector (Bellman-Ford) Routing
                Layer 3 (Dynamic Protocols)
              

              

                What is happening: Routers R1–R4 initialize without prior routing knowledge. They periodically exchange distance vector packets over UDP sockets using the distributed Bellman-Ford algorithm until cost matrices fully converge on optimal paths.
              

              
Component Tested: dvrouter.py (Distributed Bellman-Ford Engine)

            


            

              

                Scenario 4: Multi-Hop TCP 3-Way Handshake & Streaming
                Layer 4 (Reliable Transport)
              

              

                What is happening: Server D starts EchoServerTCP in LISTEN state. Host A and Host B establish concurrent TCP sessions via RFC 793 three-way handshakes (SYN → SYN-ACK → ACK), transferring byte streams with sliding window buffers.
              

              
Component Tested: mysocket.py & buffer.py (TCP State Machine & Buffers)

            


            

              

                Scenario 5: Full-Stack Multi-Hop Internet Simulation
                Layers 1–5 (End-to-End Suite)
              

              

                What is happening: The culmination test. Unifies custom switch.py (L2), dvrouter.py (L3), and mysocket.py (L4) executing simultaneously across the entire multi-hop virtual topology with 100% data integrity.
              

              
Component Tested: Full Custom Internet Stack (All Modules)

Resume Project: Breadboard Robot (Embedded Systems & Hardware)

            

            September 2025 – August 2025
          

          

            • Embedded C++ Firmware: Programmed embedded systems software in C++ on Arduino hardware, reading from multiple pin configurations (IR line/edge detection, HC-SR04 ultrasonic distance) and driving dual DC motors via L298N H-Bridge PWM.

            • Inductors & Capacitors Circuit Integration: Incorporated a 100µF electrolytic buffer capacitor across the 5V power rail to eliminate logic brownout resets caused by motor startup inrush current, 0.1µF ceramic decoupling capacitors on motor terminals for RF brush sparking noise suppression, and 1N4007 flyback diodes to clamp back-EMF inductive spikes.

            • Perception-Planning-Action Architecture: Multi-phase finite state machine structure processing pull-down button inputs, obstacle detection thresholds, and real-time motor actuation.
